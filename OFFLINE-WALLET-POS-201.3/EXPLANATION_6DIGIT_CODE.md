# 🔢 6-Digit Settlement Code - Explanation

## What is the 6-Digit Code?

The **6-digit code** (also called **Settlement Code** or **STAN**) is a unique identifier generated for each transaction batch.

## When Does It Appear?

### 1. STAN (System Trace Audit Number) - 6 digits
- Generated **on the POS device** for EACH transaction
- Format: `000001` to `999999`
- Example: `000042`, `123456`
- Purpose: Unique ID for that specific transaction

```
POS Device → Transaction #000042 created → Stored locally
```

### 2. Settlement Code - 6 digits
- Generated **on the server** when batch is synced
- Format: Random 6 digits (e.g., `456789`)
- Purpose: Proof that batch was received and processed

```
POS Device → Sync to Server → Server responds with Settlement Code: 456789
```

## Where You See the Codes:

| Location | Code Type | Purpose |
|----------|-----------|---------|
| **POS App Screen** | STAN | Customer reference |
| **POS App Screen** | Settlement Code | Proof of sync |
| **Paper Receipt** | Both | Customer keeps |
| **Dashboard** | Both | Merchant records |
| **Bank Statement** | Settlement Code | Reconciliation |

## Why Two Different Codes?

| Code | Generated By | When | Use Case |
|------|--------------|------|----------|
| **STAN** | POS Device | At payment | Customer reference, find transaction locally |
| **Settlement Code** | Server | After sync | Proof of processing, bank reconciliation |

## Summary

- **STAN (000042)**: Created immediately when customer pays
- **Settlement Code (456789)**: Created when data reaches server
- **Both are 6 digits** but serve different purposes
- **Customer should keep both** for their records
- **Merchant uses Settlement Code** to verify payment was processed
