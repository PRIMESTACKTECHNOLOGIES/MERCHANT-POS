================================================================================
                         TRANSACTION FLOW - ONLINE MODE
================================================================================

1. MERCHANT ACTION (Phone)
   ├─ Enter 6-digit code: 123456
   ├─ Enter amount: $100.00
   └─ Tap "Process Payment"
   
   ↓
   
2. APP VALIDATION (Phone)
   ├─ Check code length = 6 digits
   ├─ Validate amount > 0
   └─ Show "Processing..."
   
   ↓
   
3. API CALL (Phone → Server)
   ├─ POST /api/payment2013/redeem
   ├─ Body: { code, amount, merchantId }
   └─ Headers: Content-Type: application/json
   
   ↓
   
4. SERVER PROCESSING (Server)
   ├─ Find payment code in database
   ├─ Check if already redeemed
   ├─ Validate amount matches
   ├─ Mark as REDEEMED
   ├─ Generate reference number
   └─ Return success response
   
   ↓
   
5. RESPONSE (Server → Phone)
   ├─ Status: 200 OK
   ├─ Body: { success, reference, time }
   └─ Display receipt to merchant
   
   ↓
   
6. SUCCESS! (Phone)
   ├─ Show: "Payment Successful!"
   ├─ Reference: REF-001
   └─ Time: 14:30:45 03/04/2026


================================================================================
                        TRANSACTION FLOW - OFFLINE MODE
================================================================================

1. MERCHANT ACTION (Phone - No Internet)
   ├─ Enter 6-digit code: 888888
   ├─ Enter amount: $10.00
   └─ Tap "Process Payment"
   
   ↓
   
2. NETWORK ERROR DETECTED
   ├─ Exception caught
   ├─ Offer offline save
   └─ Generate 6-digit STAN
   
   ↓
   
3. LOCAL STORAGE (Phone)
   ├─ Create transaction record
   ├─ STAN: 000123 (auto-increment)
   ├─ Status: PENDING_SYNC
   └─ Store in Room database
   
   ↓
   
4. MERCHANT FEEDBACK
   ├─ Show: "Saved Offline"
   └─ Will sync when online
   
   ↓
   
5. LATER - WHEN ONLINE
   ├─ Merchant taps "Sync Offline Transactions"
   ├─ App batches all PENDING transactions
   ├─ Generates HMAC-SHA256 signature
   └─ POST /merchant/v1/cashout/braintree
   
   ↓
   
6. SERVER PROCESSES BATCH
   ├─ Verify HMAC signature
   ├─ Process each transaction
   ├─ Update statuses to SYNCED
   └─ Return success
   
   ↓
   
7. SYNC COMPLETE
   ├─ Show: "All transactions uploaded"
   └─ Dashboard shows new transactions


================================================================================
                      PROTOCOL 201.3 SECURITY FEATURES
================================================================================

┌─────────────────────────────────────────────────────────────────────────┐
│                    SECURITY LAYERS                                      │
└─────────────────────────────────────────────────────────────────────────┘

1. AUTHENTICATION
   • API Key verification (sk_test_mock_key_12345)
   • Merchant ID validation
   • Terminal registration

2. SIGNATURE VERIFICATION (Batch Uploads)
   • HMAC-SHA256 algorithm
   • Payload: protocolVersion|merchantId|terminalId|batchId|timestamp|nonce
   • Signature in header: X-Signature
   
3. TRANSACTION UNIQUENESS
   • 6-digit STAN (000001 - 999999)
   • Auto-incrementing counter
   • Persists across app restarts
   
4. IDEMPOTENCY
   • Prevents duplicate redemptions
   • Unique batch IDs (UUID)
   • Transaction reference tracking

5. DATA ENCRYPTION
   • Android Keystore for secrets
   • Encrypted SharedPreferences
   • Secure local database storage
